# PlugV maintenance automation

PlugV uses server-side and repository automation to help one operator maintain a reliable India-wide EV platform. Routine checks do not require a desktop computer or Codex task to be running. Automation detects problems, refreshes allowed external data and stages official vehicle discoveries; it does not publish unverified vehicle facts or live-status claims.

## Schedule

- Daily at 9:00 AM IST: GitHub checks plugv.in, critical journeys, sitemap, robots.txt, support address, content freshness and official manufacturer catalogues. New official EV links are staged in a review pull request.
- Daily at 9:30 AM IST: Vercel runs the authenticated `/api/cron/daily-operations` job. It refreshes Open Charge Map India data, probes all critical public routes and emails the configured operations recipients when a failure is confirmed.
- Daily at 9:00 AM IST: Vercel separately processes verified service and insurance email reminders.
- Every Sunday at 9:30 AM IST: runs lint, production build, launch audit, data-freshness audit, official-source link audit, and production dependency security audit.
- Every Monday at 9:00 AM IST: Dependabot checks npm packages and opens grouped update pull requests.
- Manual runs are available from GitHub Actions at any time.

When a check fails, GitHub opens one issue named `[PlugV maintenance] Automated check failed`. Later failures are added to the same issue to avoid alert noise. Runtime failures are also sent to `OPERATIONS_ALERT_EMAILS`; the safe fallback is the owner's Yahoo mailbox. GitHub notification email should remain enabled for the repository.

## Automation coverage

| PlugV surface | Automated source or control | Publication rule |
| --- | --- | --- |
| Homepage, Search, Compare and Smart Assistant | Derived from the launched catalogue | Updates when a verified catalogue change is merged |
| Explore EVs and vehicle pages | Launched catalogue plus official evidence audit | Only verified India launches may publish |
| Upcoming EVs | Rolling current/next-year catalogue and official-source discovery | Announcement, manufacturer target or official concept required |
| Knowledge Hub rankings and comparisons | Derived catalogue facts plus content-freshness audit | Review-dated facts only |
| Charging | Daily Open Charge Map India database sync; official operator feeds can be added when contracted | Source and freshness remain visible; no invented live status |
| Travel | Live route/condition services plus the charging database | Estimates are labelled; unavailable live status is disclosed |
| My EV | Database-backed saved items and daily email reminder processing | Verified consent required for email |
| Sitemap, robots and structured data | Generated by the Next.js application | Published with each deployment |
| Legal, operator identity and commercial agreements | Human-controlled | Never changed automatically |

### Vehicle discovery gate

`scripts/official-ev-discovery-monitor.mjs` watches the official India manufacturer registry and adds unfamiliar official links to `data/catalogue-candidates.json` with `REVIEW_REQUIRED` status. The daily workflow opens or updates a pull request. Before promotion, confirm the India launch state, exact vehicle/variant name, price or price status, specifications, official source URL, evidence type and verification date. This gate is intentional: automatic scraping must never silently turn a model rumour, global-only vehicle or incomplete concept into a public PlugV fact.

## Data policy

- Launched-vehicle charging and trip facts are reviewed after 60 days and block release after 120 days.
- Upcoming-vehicle facts are reviewed after 30 days and block release after 60 days.
- The BEE charging-station snapshot raises a review warning after 90 days. It does not silently claim live availability.
- Broken official source links (HTTP 404 or 410) fail the weekly audit. Bot-protected sources are reported for review.

## Operator routine

1. Review only GitHub alerts and the official-candidate pull request when notified; no daily manual audit is required.
2. Confirm changes against manufacturer, government, or charging-network sources.
3. Record the source URL and verification date with every factual update.
4. Merge Dependabot updates only after checks pass.
5. Run `npm run audit:release` before production deployment.
6. Test core journeys and support email after deployment.

## Commands

- `npm run audit:site` — live production health and SEO check.
- `npm run audit:freshness` — verification-age check.
- `npm run audit:sources` — official-source link check.
- `npm run audit:security` — production dependency security gate, including expiring reviewed exceptions.
- `npm run audit:automation` — verifies cron limits, authenticated jobs, alerting and the official-candidate review gate.
- `npm run audit:maintenance` — launch and freshness checks.
- `npm run audit:release` — full local release gate.

Domain and Zoho renewal, trademark/legal review, emergency partnerships, and third-party API contracts still require human ownership and reminders.
